# 项目简报模板（开工卡）

> **这是什么**：每个项目一张「开工卡」。AI 开工先读它，收工覆盖更新它——免得每次开工都整读几百行的更新日志，上下文被撑爆。
> **怎么用**：新建项目时在项目根目录放一份这个模板，把括号里的填上。AI 收工前只重写「现在做到哪 / 下一步」两节。

## 模板正文（从这里开始复制）

```
# <项目名> · 项目简报

> 开工读这张卡；细节见《项目更新日志.md》。AI 收工前把「现在做到哪 / 下一步」改成最新（覆盖重写，不追加）。建立【<年-月-日 时:分>】。

## 1. 这是什么

（一句话：类型 + 根目录路径 + 这个项目是干嘛的。）

## 2. 现在做到哪

- 【<时间>】<最近干的一件事，一行一条，最多留 4 条。>

## 3. 下一步

（下一件要干的事；没有就写「待定」。）

## 4. 别碰 / 必须守

- 《项目更新日志.md》默认别整份读；查旧账先搜 `## 【` 定位，只读那一段。
- （这个项目特有的规矩。）

## 5. 关键文件

| 文件 | 是什么 |
| --- | --- |
| （入口 / 配置 / 最常改的文件） | （一句话） |
```

## 为什么要这样设计

- **简报是「活索引」**：常驻开工位，几十行就够，越短 AI 读得越准。
- **日志是「档案」**：默认不读，按行号点名才读那一段。
- 这套「小状态卡 + 大档案按需取」的分层，跟学界头部项目 Letta/MemGPT 的「core memory / archival memory」是同一个思想——不花钱、纯文本、坏不了。
